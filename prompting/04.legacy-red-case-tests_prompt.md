## 대화 전문

### Turn 1 - User Prompt

```text
[p] 너는 C++ QA TEST 설계 전문가야
[T] @docs/Regacy_Code_리팩토링_테스트_계획.md @docs/PRD.md 문서를 참조해서 레거시 코드의 결함으로 발생 할 수 있는 테스트를 설계하려고 해.
   - 구현코드 수정금지, TEST코드만 생성
   - 코드의 결함으로 발생하는  RED CASE 확인
   - C++17 문법을 사용
[F] 설계 테스트 케이스 코드, 테스트케이스를 표로 요약한 문서(HTML파일 형식)
```

### Turn 1 - AI Progress

```text
레거시 결함을 드러내는 RED CASE 중심으로 테스트 코드와 HTML 요약 문서를 만들겠습니다. 먼저 PRD, 테스트 계획, 현재 C++ 구조와 테스트 프레임워크 상태를 확인해 “프로덕션 코드 수정 없이” 추가 가능한 테스트 형태를 정하겠습니다.
```

### Turn 1 - AI Answer

```text
RED CASE 테스트 설계 파일과 HTML 요약 문서를 생성했습니다.

생성 파일:
- `tests/red_cases/legacy_red_cases_test.cpp`
- `docs/legacy_red_case_test_summary.html`

테스트 범위:
- `RED-04`: 감정 분석과 감정 필터 기준 불일치
- `RED-05`: 카테고리 분석과 카테고리 필터 기준 불일치
- `RED-14`: 세션 정적 상태 오염
- `RED-15-A`: 필터링 중 사용자 입력 원문 stdout 출력
- `RED-15-B`: 디버그 로그 기본 활성화 위험

검증:
- linter 오류 없음
- `g++ -std=c++17 -I src/cpp -fsyntax-only tests/red_cases/legacy_red_cases_test.cpp` 통과
- 구현 코드와 빌드 스크립트는 수정하지 않았습니다.

참고:
- 현재 프로젝트에는 테스트 타깃이 없어서 실제 테스트 실행은 하지 않았습니다.
- 테스트 파일은 Catch2가 있으면 Catch2로 동작하고, 아직 Catch2가 연결되지 않은 환경에서도 읽기/문법 검사가 가능하도록 최소 fallback runner를 포함했습니다.
```
