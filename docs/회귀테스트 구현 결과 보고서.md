## 1. 개요

- 작업 일시: 2026-05-22
- 작업 목적: `docs/회귀테스트 계획.md`에 따라 C++17, CMake, Catch2 호환 Golden Master 회귀테스트를 구현한다.
- 작업 제약: `src` 폴더의 구현 코드는 수정하지 않는다.
- 핵심 결과: Golden Master 회귀테스트 18개 구현, CMake 테스트 타깃 추가, 전체 테스트 Green 확인.

## 3. 테스트 구성

### 테스트 타깃

- CMake target: `feedback_analyzer_golden_master_tests`
- CTest name: `golden_master`
- Test source: `tests/golden_master/golden_master_regression_test.cpp`

### Catch2 호환 방식

- `Catch2::Catch2WithMain` 타깃이 있으면 `GOLDEN_MASTER_USE_CATCH2=1`로 Catch2 테스트로 빌드된다.
- 현재 환경처럼 Catch2가 발견되지 않는 경우에도 동일한 `TEST_CASE`, `REQUIRE`, `REQUIRE_FALSE` 형태를 유지하는 C++17 fallback runner로 실행된다.
- 이 방식은 이후 Catch2 의존성이 설치되면 테스트 코드를 유지한 채 Catch2 실행 모드로 전환할 수 있게 한다.

### HTTP 테스트 방식

- 실제 포트를 열지 않는다.
- fake `httplib` 경계를 정의한 뒤 `src/cpp/main.cpp`를 테스트 translation unit에 include한다.
- 등록된 route handler를 직접 호출해 `GET /`, `POST /analyze`, `POST /upload`, `POST /filter`, `GET /download` 흐름을 검증한다.

## 5. 실행 명령

```powershell

cmake --build "build" --target feedback_analyzer_golden_master_tests
ctest --test-dir "build" --output-on-failure -R golden_master
build\feedback_analyzer_golden_master_tests.exe
```

## 7. 품질 확인

- `ReadLints` 결과:
  - `tests/golden_master/golden_master_regression_test.cpp`: linter error 없음
  - `CMakeLists.txt`: linter error 없음
- 테스트 독립성:
  - 각 테스트 시작 시 `Session`, 필터 다운로드 상태, fake `httplib` route 상태, DEBUG 로그 상태를 초기화한다.
- 포트 안전성:
  - fake `httplib`를 사용하므로 테스트 실행 중 실제 네트워크 포트를 열지 않는다.

## 8. 주의 사항

- 현재 환경에서는 Catch2 패키지가 CMake에서 발견되지 않아 fallback runner로 실행되었다.
- 테스트 소스는 Catch2 매크로 형태와 호환되도록 작성되어 있으므로, Catch2 설치 후 `Catch2::Catch2WithMain`이 발견되면 Catch2 모드로 빌드된다.
- GM-16은 현재 화면이 사용자 원문을 결과 목록으로 직접 렌더링하지 않는 동작을 기준으로, raw HTML 입력이 응답에 실행 가능한 markup으로 반영되지 않는지를 검증한다.

## 9. 결론

Golden Master 회귀테스트 18개가 구현되었고, CMake/CTest에서 전체 Green을 확인했다. 이후 리팩토링 단계에서는 `ctest --test-dir build -R golden_master --output-on-failure`를 각 커밋 후 실행해 상태, CSV, 분석/필터, 다운로드, 입력 검증, 로깅 보호 회귀를 빠르게 확인할 수 있다.
