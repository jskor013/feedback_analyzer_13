Legacy RED CASE Test Summary

이 문서는 docs/Regacy_Code_리팩토링_테스트_계획.md와 docs/PRD.md를 기준으로 설계한 레거시 결함 재현 테스트를 요약한다. 테스트 코드는 tests/red_cases/legacy_red_cases_test.cpp에 작성되어 있다.

주의: 아래 테스트는 리팩토링 전 현재 레거시 코드에서 실패하는 것이 정상인 RED CASE다. 목적은 결함을 먼저 고정하고, 이후 리팩토링 단계에서 Green으로 전환되는지 확인하는 것이다. 구현 코드와 빌드 스크립트는 수정하지 않았다.

테스트 케이스 요약

ID 테스트명 근거 문서 결함 설명 테스트 입력 기대 결과 현재 예상 결과 Green 전환 기준
RED-04 감정 분석과 감정 필터 기준 일치 리팩토링 테스트 계획 RED-04, PRD 3.6 분석 기준과 필터 기준이 서로 달라 같은 피드백을 다르게 판단한다. 배송이 빠르고 정확합니다 분석의 긍정 개수와 긍정 필터 결과 개수가 같다. 분석은 중립, 필터는 긍정으로 판단할 수 있다. 분석과 필터가 같은 감정 판단 기준을 사용한다.
RED-05 카테고리 분석과 카테고리 필터 기준 일치 리팩토링 테스트 계획 RED-05 분석은 대표 키워드 기준을 사용하고 필터는 하위 키워드 중심으로 동작해 결과가 어긋난다. 제품 품질이 중요합니다 품질 분석 개수와 품질 필터 결과 개수가 같다. 분석에는 포함되지만 필터에서는 제외될 수 있다. 분석과 필터가 같은 카테고리 판단 기준을 사용한다.
RED-14 세션 초기화 시 이전 피드백 상태 제거 리팩토링 테스트 계획 RED-14 정적 세션 상태가 테스트와 요청 사이에 남아 상태 오염을 일으킬 수 있다. 세션에 이전 테스트 데이터 추가 후 초기화 호출 초기화 후 현재 피드백 목록이 비어 있다. 초기화 함수가 실제 상태를 비우지 않는다. 반복 테스트 실행 시 이전 상태가 다음 테스트에 영향을 주지 않는다.
RED-15-A 필터링 중 사용자 입력 원문 stdout 출력 금지 리팩토링 테스트 계획 RED-15, PRD 3.4, PRD 3.6 필터링 로직이 결과 피드백 원문을 표준 출력에 직접 출력해 개인정보 노출 위험을 만든다. 고객 전화번호 010-1234-5678 포함된 민감 피드백 표준 출력에 피드백 원문이 포함되지 않는다. 필터 결과 피드백 원문이 stdout에 출력될 수 있다. 운영 로그와 디버그 출력 정책이 분리되고 원문 출력이 통제된다.
RED-15-B 디버그 로그 기본 비활성화 리팩토링 테스트 계획 RED-15, PRD 3.3, PRD 6.3 디버그 로그 기본값이 운영 환경에서 원문 또는 내부 정보를 노출할 수 있다. 애플리케이션 기본 Logger 상태 디버그 모드가 기본 비활성화 상태다. 디버그 모드가 기본 활성화 상태일 수 있다. DEBUG 로그는 명시적 설정 조건에서만 출력된다.
